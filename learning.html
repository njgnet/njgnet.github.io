네트워크·인프라

네트워크와 접근 통제

2026.03.30

ACL 접근 제어목록

표준 ACL과 확장 ACL의 차이, 정책 순서와 적용 방향을 Packet Tracer에서 확인했습니다.

학습한 내용

  • 표준 ACL은 출발지 주소를 기준으로 필터링하고, 확장 ACL은 출발지·목적지·프로토콜까지 제어합니다.
  • 좁은 범위의 조건을 먼저 작성해야 하며 마지막에는 명시되지 않은 deny any가 적용됩니다.
  • ACL을 인터페이스에 적용한 뒤 show access-list로 정책과 매치 상태를 확인했습니다.
access-list 10 permit host 192.168.0.10
access-list 10 deny 192.168.0.0 0.0.0.255
access-list 10 permit any
interface gi0/0
 ip access-group 10 out

실습에서 확인한 점 정책 내용뿐 아니라 작성 순서와 인터페이스의 in/out 방향이 통신 결과를 바꾼다는 점을 확인했습니다. 이 경험은 1차 프로젝트에서 본사·지사 ACL 기준을 만들고 반복 테스트하는 과정으로 이어졌습니다.

VPN·IPsec 및 서버 기초

VPN 통신 구조와 Linux·Windows Server의 기본 서비스를 직접 설정했습니다.

실습 범위

  • VPN과 IPsec의 동작 구조 및 네트워크 구간별 통신 흐름
  • Linux 계정 관리, NFS·Samba 파일 공유, DNS·HTTPS, rsyslog
  • Windows Server 설치와 DNS 설정, Linux 계정 정책 비교
  • Packet Tracer를 활용한 라우터·스위치 설정 개별 실습

정리 장비 설정만 보는 것이 아니라 서버 서비스와 네트워크가 실제로 어떤 흐름으로 연결되는지 함께 학습했습니다.

방화벽과 침입 탐지

2026.05.07–08

pfSense 방화벽 구성

WAN·LAN 인터페이스부터 정적 라우팅, 방화벽 정책과 원격 접속 VPN까지 구성했습니다.

구성 과정

  1. 가상 머신에 WAN과 LAN 어댑터를 나누고 pfSense를 설치했습니다.
  2. DHCP 대신 인터페이스 IP와 게이트웨이를 직접 할당했습니다.
  3. GNS3 환경에서 LAN·WAN 네트워크로 가는 정적 경로를 등록했습니다.
  4. WAN 기본 차단 상태를 확인한 뒤 필요한 출발지와 목적지에 대해서만 허용 규칙을 작성하고 웹 통신을 시험했습니다.
  5. CA와 서버 인증서, 사용자를 생성한 뒤 OpenVPN 서버와 클라이언트를 설정해 터널 IP가 할당되는지 확인했습니다.

실습에서 확인한 점 방화벽 규칙만 추가해서는 통신이 완성되지 않았고, 인터페이스·게이트웨이·라우팅·정책을 함께 확인해야 했습니다.

2026.05.12

Suricata 네트워크 침입 탐지

홈 네트워크와 캡처 인터페이스를 지정하고 커스텀 ICMP 탐지 룰을 만들어 시험했습니다.

설정과 검증

  • suricata.yaml에 HOME_NET과 AF-Packet 인터페이스를 현재 환경에 맞게 설정했습니다.
  • suricata-update로 룰셋을 갱신하고 ET/Open 소스를 활성화했습니다.
  • 로컬 룰 파일에 ICMP 경고 규칙을 추가한 뒤 설정 문법을 테스트했습니다.
  • Kali Linux에서 Ping을 전송하고 fast.log와 eve.json에서 경고가 발생하는지 확인했습니다.
  • 복잡한 JSON 로그는 jq를 이용해 alert 이벤트만 필터링했습니다.
alert icmp any any -> $HOME_NET any (msg:"Ping"; sid:1; rev:1)
suricata -T -c /etc/suricata/suricata.yaml -v
tail -f /var/log/suricata/eve.json | jq 'select(.event_type=="alert")'
2026.05

통합 모니터링과 로그 분석

여러 탐지·관제 도구를 설치하고 이벤트가 수집되는 흐름을 확인했습니다.

다룬 도구

  • Wireshark 패킷 캡처와 필터링
  • Snort 2·3, Suricata 네트워크 침입 탐지
  • OSSEC 호스트 침입 탐지와 Wazuh 기반 보안 모니터링
  • Graylog·Splunk 로그 분석, Nagios·GoAccess·Zabbix 모니터링

정리 탐지 룰이 동작하는 것과 운영자가 로그에서 필요한 이벤트를 빠르게 찾아내는 것은 별개의 문제라는 점을 배웠습니다.

2026.05.21

Python을 이용한 자동화

반복 확인 작업을 코드로 바꾸는 기초 실습을 진행했습니다.

실습 내용

  • 가상환경과 라이브러리 경로를 확인하고 필요한 모듈을 설치했습니다.
  • 리스트에 저장된 서버·웹사이트에 순서대로 접속해 성공 여부를 확인했습니다.
  • 파일을 확장자별 디렉터리로 분류하고 로그를 날짜 기준으로 백업했습니다.
  • /etc/passwd에서 로그인 가능한 계정을 찾아 CSV 보고서로 저장했습니다.
  • 예외 처리를 추가해 실행 중 오류가 전체 작업을 중단하지 않도록 구성했습니다.

프로젝트 연결 이후 시스템 점검 결과를 같은 형식으로 모으는 스크립트 틀과 자동 실행 아이디어를 정리할 때 이 학습 경험을 활용했습니다.

DVWA 웹 취약점 실습

보안 수준과 입력값을 바꿔가며 취약점이 발생하는 조건과 결과를 확인했습니다.

  • 정상 요청과 공격 요청의 차이를 비교했습니다.
  • 공격이 성공하는 입력 조건을 확인하고 보안 수준 변경 후 결과를 다시 시험했습니다.
  • 단순히 명령을 실행하기보다 요청·응답과 서버 측 처리 흐름을 함께 살펴봤습니다.

WebGoat·Metasploit·WAF

교육용 취약 환경을 통해 공격자의 접근 순서와 방어 장비의 역할을 학습했습니다.

  • WebGoat에서 웹 취약점별 문제와 요청 흐름을 확인했습니다.

  • WAF가 HTTP 요청을 검사하고 정책에 따라 차단하는 위치와 역할을 정리했습니다.
